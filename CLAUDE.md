# Peakhill NBA Survivor: notes for changes

- Static app (`index.html`, `styles.css`, `src/*.js`), no build step. One site, two leagues: NBA at the root, NHL at `nhl/` (same code; `src/config.js` has each sport's settings, and `PHS_SPORT=nhl` selects hockey in Node). Check a change in both leagues, including `nhl/?demo`. Rules engine in `src/league.js`, tests in `test/` (`npm test`). Preview with `npm run serve` and `/?demo`.
- **Ask the user before adding a "What's new" entry.** Entries in `src/updates.js` pop up for every player on their next visit, so never add one on your own. When a change affects how people play or what they see (rules, scoring, picks, screens they use), say so and ask whether it needs an announcement; add one (at the top of that league's list, next `id`, the date, short plain-language bullets) only if the user says yes. Commissioner-only changes (the Commissioner tab, SQL, data job, internal fixes) never get one.
- If a change alters the rules covered by the first-login tour (`TOUR` in `src/app.js`) or the Rules tab, update those too.
- League rules (bars, lives, card numbers and more) can be changed by the commissioner in the Commissioner tab. `src/config.js` has the defaults; `src/settings.js` applies the overrides. A new rule number the commissioner should control goes in `settings.js` (`LIMITS` plus the week or season paths) and the Commissioner tab form.
- Before pushing, run `npm test` and the smoke test (`npm run smoke`, needs Playwright). CI runs both on every PR, and a red CI must not be merged. After resolving merge conflicts, run them again: a bad merge took the site down once.
- **Shipping is the default: open the PR and merge it** (squash) once CI is green, without asking. Ask for approval first only when the change is high risk: it needs SQL run in Supabase before it can go live, touches accounts, sign-up, security or row-level security, could lose or rewrite league data (picks, cards, scores, burns), changes how past weeks are scored, or removes something players use. Say which of these applies when you ask.
- Database changes ship as a re-runnable SQL file in `supabase/` that the commissioner runs in the Supabase SQL editor before merging. Then rebuild the NHL league's file with `PHS_SPORT=nhl node scripts/nhl-sql.mjs` (the tests check it). Both leagues share one Supabase project (NBA in `public`, NHL in the `nhl` schema, accounts shared), so the commissioner runs the NBA file and then `supabase/nhl/setup.sql`.
- Each league has its own "What's new" list in `src/updates.js`.
